# 磁巡检 v2：答辩定版与真实巡检的最短收口路径

日期：2026-10-20。结论：**本次不改核心算法，固定“主动观测、横向巡检、埋深独立许可”的现有 v2；真实巡检先采用已知目标短直段的 F 剖面。** 本次固化的是可核对的算法与配置基线，现场参数与自主执行许可仍须由真实输入和艇体试验确定。

## 1. 为什么现在可以停止改算法

当前实现已经把此前的模型失配风险变成了明确的输出约束：

- `pipeline.py::_estimate_current_scan` 在未提供标定、形状支持不足或缺少新鲜离底高度时，清空垂距、埋深及其不确定度；横向中心另行判定。
- 专用 `inspection`、`flythrough` 配置均为 `inspection.enabled: true`、`allow_uncalibrated_depth: false`，旧的埋深反演开关亦关闭。
- ROS 适配器禁止非仿真巡检启用未标定深度逃生口；`shallow_survey` 多横切仍明确限制为仿真模式。
- 已有独立目标身份、观测失鲜、路线偏差与执行撤权机制。增加一个总置信度或重复一套拒绝逻辑，没有证据能补上物理标定与实际部署时序。

单一、对称且单调衰减的异常满足半高交点中点对应中心，但宽度到距离仍依赖场形系数。未知多芯、铠装、邻缆或共同导航偏差可能同时破坏这些条件。**中心与埋深分开许可具有明确理由；横向可用也仍然有适用边界。** 详见[跨场形可辨识性](CROSS_SHAPE_IDENTIFIABILITY.md)和[巡检输出契约](INSPECTION_CONTRACT_20260926.md)。

因此不再以“找出一种能覆盖所有场形的 FWHM 修正”为答辩结束条件。连续幂律、多高度斜率、向量物理反演及独立研究目录中的方法继续保留各自的研究身份，未经实测与部署验证，不替换当前巡检入口，也不并入本次冻结结果。

## 2. 固定什么，不再反复选型

| 项目 | 本次固定的选择 | 后续修改的必要触发条件 |
| --- | --- | --- |
| 总工作流 | 先验引导 → 检测 → 主动确认 → 有界接入 → 跟踪／撤权 | 实际任务流程存在可复现的缺口 |
| 信号检测 | 现有滑窗、迟滞、连续帧证据 | 实测底噪、干扰或采样率使当前门限失效 |
| FWHM | 背景修正半峰、双侧交点、覆盖及形状诊断 | 原始实测完整横切出现可复现错误 |
| 轨迹 | 首验选已有浅角单次穿越 F；保留有界扩幅机制 | 实测转向、覆盖或停止包络证明既有轨迹不可执行 |
| 埋深 | 无独立标定与新鲜高度时保持 `null`，`depth_valid=false` | 取得独立几何真值、安装一致性与留出证据 |
| 跟踪 | 保留现有预瞄、限幅、路线与身份连续门 | 同次记录显示估计有效而跟踪执行不满足现场要求 |

本次不默认增大 zig-zag 幅度。扩大横切只可能改善测线覆盖，不能自行确定未知场形的距离比例，也不能解决邻缆身份。对欠驱动载体还须同时核对转弯、接入和故障滑行空间。当前分档半幅与浅角轨迹按各自配置保留，不把不同试验的参数拼成“通用最优值”。

配置基线为 [`cable_tracking_v2_flythrough.yaml`](../../../brain_linux/src/auv_cable_tracking_v2/config/cable_tracking_v2_flythrough.yaml)，它含仿真侧向先验，**不是拿来直接下海的批准参数文件**。现场应从这条算法路径派生单独任务配置，填写经核实的目标、边界和实际载体参数，保留深度禁用约束。使用真实时钟时，现有合成先验会被入口拒绝；不得靠重命名来源或开启仿真时钟绕过。

## 3. 只保留两条后续路径

**路径 A：先完成真实横向巡检，推荐。** 核心算法保持不变，首个对象选经独立核实的孤立、短直线目标，已知目标侧向与可进入走廊。先记录原始传感器输入和被动算法输出；确认中心、身份与时效后，再按既有现场合同验证闭环执行。没有物理声呐时可用独立测绘路径，但测绘必须同时约束真实线位与邻源排除，不能只有一条标称地图线。

这条路径的交付目标是“指定短段的横向观测与有限巡检”，埋深保持空值。需要通过的是同一真实任务的输入、估计、下发、板端接收与运动结果，不能把不同日期的片段拼成一次整链验收。目标 Jetson 的连续输入输出、真实转弯／滑行以及上级处置仍是待验证项，详见[现场首验剖面](INSPECTION_V2_FIELD_FIRST_PROFILE_20260927.md)、[同次时序合同](INSPECTION_SAME_SESSION_TIMING_ENVELOPE_20260928.md)及[现场冻结矩阵](INSPECTION_V2_FREEZE_AND_FIELD_GATE_20260927.md)。

**路径 B：若首验必须交付埋深，只做一次有数据依据的标定接入。** 使用已有 `shape_calibration.py` 和标定工具，先选最简单的常数映射 `z=κW`；只有开发扫描显示系统性系数漂移时才考虑现有仿射映射。随后接入独立、同步且通过外参换算的传感器离底高度，得到 `d=z-h`。这里 `z` 是传感器到导线参考轴的垂距，`d` 是该参考轴低于海床的深度；若报告电缆顶部覆盖厚度，还须另有外径及几何定义。

按[标定协议](SHAPE_CALIBRATION.md)，常数映射至少覆盖两个不同独立真值距离；仿射至少三个。默认流程至少五条有效训练扫描和五条留出扫描，按完整扫描／会话隔离。若用数据选择常数或仿射方案，应再保留未参与选型的最终测试集。现有 0.2 m MAE／0.5 m P95 是工程审计默认值，须在看真实测试结果前确认任务是否接受，不能视为行业统一标准。仅有 `accepted=true`、文件哈希或来源标签均不授予现场许可。

本仓当前没有满足契约的真实受控横切包；这条路径现阶段不能靠软件修改宣称完成。若最终测试仍出现“大误差但发布有效”，本轮不再叠加新拟合器，退回路径 A；保留原始数据与失败原因，再单独立项研究场模型。

## 4. 一次修改的边界与停止条件

如果真实输入揭露坐标、杆臂、原生时间戳、离底高度或标定加载的明确接线问题，允许开一个独立补丁处理该问题，连同数据包、回归和新版本哈希一起保存。采样率、阈值和轨迹参数变更也必须绑定数据与任务配置；传感器型号、安装或作业域改变，不能沿用旧标定的发布资格。

补丁完成后停止修改的判据为：

1. 相同原始数据能复算，输入坐标与时钟可追溯；预先声明的正常例满足实际任务指标。
2. 未标定／高度失鲜时不输出埋深；身份冲突、输入失鲜与越界条件按既有合同撤权，失效旧值不作为新结果沿用。
3. 相关既有回归通过，源码、配置、标定与原始包均有快照。部署版还需同次板端接收和运动证据；零命令不等于艇已经停住。

这三个条件满足后，性能优化与扩大适用海域进入下一版本。若只有仿真误差小幅改善或新方法离线拟合更好，不据此重新打开当前答辩版本。

## 5. 答辩主讲与证据选择

推荐主讲口径：

> 本文面向有目标先验的海缆巡检，通过主动穿越获取空间磁剖面，显式计算半高交点和横向中心，并将横向定位、目标身份、埋深和执行许可分别判断。在限定仿真条件下已完成有限路线巡检与无源拒绝；未知场形或缺少独立标定时不发布埋深。真实部署先验证已知短段的横向巡检，再按独立几何标定开放埋深输出。

主结果使用原[仿真发布包](../../results/v2/inspection_simulation_closure_20260928/README.md)：孤立直线目标、理想导航、零横流、6 m 先验横偏下，两种场形各 3/3 完成且覆盖 70 m 核心段，完整核心航迹横偏 MAE 0.771–0.774 m、最大 1.321 m；无源 3/3 拒绝，埋深为空。它们是已保存的历史结果；本次没有重新运行这九趟，也不将六个成功样本表述为海况成功概率或当前 ROS 实时整链通过。

若被问“模型失配是否已经解决”，回答：**已限制其通过未标定深度输出影响任务的路径；未知模型本身仍需独立验证。** 邻缆与共同导航偏差还可能影响横向位置，不能声称禁用埋深就保证任意磁场下的正确跟踪。对应条件由独立目标证据与导航／安装验收约束。
