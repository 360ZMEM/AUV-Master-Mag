# 3DM-GX3-25 原生计时器：最快的 IMU 时间来源收口路径

在[现行 VxWorks 接收代码](../../../csd_vx6.8_lastest/com.c)与本机保存的[3DM-GX3-25 单字节协议说明](<../../../相关附件和参照/原始AUV部分潜在技术细节/3DM-GX3-25 Single Byte Data Communications Protocol.pdf>)之间发现了可直接利用的字段。固件每轮发送 `0xCF`，协议第 23 页规定其响应固定为 31 字节：六个姿态/角速率浮点量占字节 2--25，字节 26--29 是**传感器自身 32 位 Timer**，最后两字节是对之前字节求和的 16 位校验和。协议第 51 页给出计时器频率 `62,500 tick/s`、约 19 小时回绕；第 38 页给出校验和算法。这个 Timer 是传感器响应中的原生时间锚，仍须确认它与本次姿态计算周期的关系，不能仅凭字段名称宣称绝对采集时刻。

当前 `com.c` 的 `Recv_From_IMU()` 只检查首字节 `0xCF`，忽略参数 `length`，没有执行协议校验和；`UartRecvFormIMUTask()` 随后把任意读入长度复制到 32 字节 `From_IMU_Buf`，而 `DataProcess.c` 的 `Unpack_Data_From_IMU()` 只读前 25 字节的姿态和角速度，丢弃了 Timer 与校验和。旧设计说明曾声称该接收函数检查帧头、帧尾、校验和与长度，现行源码不支持这项表述。这是源码与文档的明确错配，且意味着第一个字节正确的短帧或损坏帧也可能被当作姿态输入；是否实际发生需原始串口日志证明。

[图像和协议/固件源码哈希](publication/fwhm_v2_experiment_results/data/43_gx3_timer_provenance_gap_manifest.json)固定这张源码审计图的来源。图是协议字段与代码行为的诊断示意，不是物理观测波形。

最快的工程改动应局限在 IMU 接收边界，并采用版本化的上行扩展或独立诊断通道，避免直接改写旧 `$AUV` 帧布局：

1. 在 PC104 串口接收处按固定 31 字节拼帧；先检查长度、`0xCF` 帧头、16 位校验和及有限数值，再原子化更新姿态。禁止在确认长度前复制到 32 字节全局缓冲。
2. 同一有效响应保留原始 32 位 Timer、板端收帧时刻与单调接收序号；相同 Timer 拒绝刷新。只在接近 `2^{32}` 时接受有界回绕，普通倒退或长时间断流必须重新建立时间基准，不能静默重置。
3. 通过版本化扩展将 Timer、板端收帧时刻和有效位送至 Jetson；桥端从同一帧恢复 ROS IMU 时间戳、序号及年龄，核对原始 Timer 到组包/接收的延迟。固件和桥同时保留旧字段，未启用新版本时保持巡检 Hold，避免把组包时钟冒充为传感器时钟。
4. 在真实 3DM-GX3-25 与 PC104 上做五组原始录制：健康持续、拔掉 IMU 串口、重复旧应答、损坏校验和、Timer 回绕或设备重启；对照 ROS IMU 是否停发、导航是否撤销、桥是否进入被动零输出。另以独立姿态真值给出协方差保守上界，并测量传感器响应到 ROS 的时延分布，再冻结门限。

独立的[离线 `0xCF` 解码器](../../../tools/decode_gx3_cf.py)已按本地协议实现完整帧长、校验和、有限数值、Timer 解码及有界回绕；[合成单测](../../../tests/test_gx3_cf_time_provenance.py)覆盖短帧、损坏帧、重复、重启/倒退和正常回绕。它是未来固件实现的可复核参考，**没有改动当前 PC104 固件，也没有接入真实串口或 `$AUV` 上行**。新[IMU 采样来源预检](INSPECTION_IMU_ACQUISITION_PREFLIGHT_20260927.md)可在取得上述原始包和对时映射后检查逐样本输出；当前空模板仍拒绝现场准入。

现已进一步新增[隔离 C99 接收候选](../../../csd_vx6.8_lastest/inspection_v2_candidate/gx3_cf_guard.c)：逐字节接收任意分段串口流，仅在完整 31 字节、校验和、有限值和有界递增 Timer 均合格时输出新样本；损坏帧会搜索下一个帧头重新同步。主机编译的故障注入覆盖分段、垃圾字节、损坏校验和、重放、设备重启/倒退、Timer 回绕及 NaN，AddressSanitizer/UBSan 运行通过。候选默认以 5 s 最大 Timer 间隔做拒绝示例；设备重启或更长断流需要显式重新准入，5 s 尚非现场阈值。该 C 目录不在现有 VxWorks 构建链中，VxWorks 工具链适配和串口实录仍待完成。

为避免挤占旧 `$AUV` 已分配字段，[独立 IMU 来源侧帧 v1](INSPECTION_IMU_SIDECAR_V1_CONTRACT_20260927.md)固定了 48 字节版式：同一已验原始帧的校验和、样本序号、传感器 Timer、PC104 完整收帧时刻、姿态/角速度与 CRC32。隔离 C 编码器和 Python 解码器已逐字节黄金向量一致；尚未选择物理端口、接入固件、启动 ROS 接收节点或提供姿态协方差。下一阶段必须让旧 `$AUV` IMU 发布与该侧帧互斥，不能把两路不同可信度的姿态同时送给定位。
