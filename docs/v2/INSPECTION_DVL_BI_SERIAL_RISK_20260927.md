# DVL `:BI` 串口入口风险与隔离候选

图 44 的 ROS 配对解决姿态来源和时间匹配，但不证明 PC104 输入本身已受保护。现行 `com.c` 的 `Recv_From_DVL_BI()` 搜到 `:BI` 就置接收标志；`DataProcess.c` 的 `Unpack_Data_From_DVL_BI()` 连续用 `strstr()` 查逗号并直接 `atoi(ptr+1)`，缺逗号时存在空指针解引用路径。三轴值和收帧时间也分次写入、分次读出，尚未见同次原子快照保护。这是源码风险审计，并非实艇崩溃复现。

隔离目录新增 [C99 有界解析候选](../../../csd_vx6.8_lastest/inspection_v2_candidate/dvl_bi_guard.c)：只在完整 `:BI` 行、四个有界数字字段和末尾 `A` 有效标志同时成立时，输出一次不可拆分的三轴速度、序号和完整收帧时刻。分段、截断、缺逗号、无效标志、越界数字及随机字节均不能刷新样本。主机 `pytest`、ASan/UBSan 与 20 万个随机七字节块故障注入通过；复核入口为 `tests/test_dvl_bi_guard_c.py`。现有 DVL 实验文本只有 `:WI`/`:WD`，缺真实 `:BI` 底跟踪原始记录，因此这一候选未进入现行 VxWorks 构建，也不改变本文实物结论。

若后续现场要使用这条速度输入，最小核对顺序是：取得真实 `:BI` 原始行与设备状态字段含义，按实际格式确认有界解析；PC104 解析任务把三轴、序号和收帧时刻作为一个样本写入，`$AUV` 构包任务一次性快照；随后做畸形帧、断流、底锁丢失与同次导航/停车测试。没有这些证据时，ROS 侧受界配对只能作为合成软件验证，不能把 DVL 宣称为已验收的物理输入。
