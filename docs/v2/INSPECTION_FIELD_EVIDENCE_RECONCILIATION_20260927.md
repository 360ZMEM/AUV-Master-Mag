# v2 现场证据的本机来源复核

当前最稳妥的答辩口径不是“实物完全没有验证”，而是分清**已有底层实物台架记录**、**本机可重算的合成 v2 巡检链**与**尚缺的同次实艇验收**。对当前 Linux 工作区的指定原始路径和派生报告进行只读清点，[机器清单](publication/fwhm_v2_experiment_results/data/inspection_v2_field_source_readiness_20260927.json)记录每个本地文件是否存在、大小与 SHA-256；它不搜索团队其他电脑，因此不能证明原始包在外部也不存在。

| 证据层 | 目前可引用的观察 | 本机复核边界 | 对 v2 现场许可的作用 |
| --- | --- | --- | --- |
| TMR--ArUco 实物联合实验 | 现存报告记载 777 个同步点、9 个候选单调腿；v2 适用性审计双侧 FWHM 有效 0 条 | 对应 ADC NPZ 与相对位姿日志未在当前路径找到；原轨迹是自由手持，缺完整双侧横切和海床基准 | 可说明实际空间磁测与质量拒绝；不能标定埋深或证明艇载横向任务 |
| PC104 固件回声 | 现存派生摘要记载 1,001 个配对事件，应用路径首次回声 RTT P99 为 315.606 ms | 原始 300 s 时序包未在当前工作区找到；RTT 非共享时钟单向时延 | 可作为既有执行脑接口时序先验，不能替代本版巡检撤权收帧 |
| PC104 watchdog/故障注入 | 现存派生摘要记载 5/5 次自然心跳中断触发 Remote，观测最大 1058.118 ms，台架命令快照保持零 | 原始 `fault_timeline.csv`、板端状态与 v2 同次运行包未在当前路径找到；旧实验隔离了真实电压/DVL 与非零动力 | 可说明底层零执行量安全机制曾在物理板验证；不能直接作为本次 v2 Hold 的真实停船距离 |
| v2 本机同次链 | 原始 PVS CSV、桥/界面状态轨迹和哈希俱在；失鲜后 241/241 周期撤权且 UDP 零 RPM | 磁场、声呐、上行健康和动力学是合成或夹具；PC104 未连接 | 支持本版软件合同与答辩演示，不解锁实艇 |
| 目标身份 | 本地 43 份 bag 元数据中目标声呐观测、质量消息均为 0；无物理批准标定 | 这是指定目录的清点；可信测绘线或已确认航迹也可作独立线索，但本机尚无经审查的任务记录 | 多缆环境不得凭单个磁峰宣布目标完成 |

因此现场最短路径仍是[冻结矩阵](INSPECTION_V2_FREEZE_AND_FIELD_GATE_20260927.md)所列两个包：先在**已知、短直、边界可测的孤立目标线**上给出可信的目标先验（可为审查后的窄测绘线，不强制依赖声呐），再记录同一故障时刻的 v2 命令、PC104 收帧、真实地速、滑行距离与走廊净距。通过后可先冻结横向目标巡检；埋深另用多垂距完整横切、独立几何真值和同步离底高度解锁。上述历史台架数字可作为实验设计先验，不能直接代入现场 Hold 预算或 FWHM 系数。

若原始实验包位于另一台电脑，按清单中的相对目录结构挂载或复制到一个只读目录，即可重新清点，不会改写本次基线：

```bash
python3 tools/audit_v2_field_source_readiness.py \
  --raw-root /path/to/transferred_project_root \
  --output-json /tmp/inspection_v2_field_source_readiness_recheck.json
```

本机清点结果为 5 类指定原始包均不完整，8 份派生/历史报告或清单可读取；`field_release_authorized=false`。若收到新原始包，应先核对其时间轴、原始帧与标注/报告哈希，再更新现场准入结论；单纯把文件复制到目录不能证明它满足 v2 同次链和运动包络要求。
