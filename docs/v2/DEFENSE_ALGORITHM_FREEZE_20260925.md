# FWHM v2 答辩基线与真实巡检收口决定

决定日期：2026-09-25。基线标识：`fwhm-v2-defense-20260925`。

> 2026-09-26 增量：本页保留为历史决定。后续授权新增了默认关闭的独立巡检模式，横向定位与埋深授权分开，并验证有界重扫与故障保持；实现状态及证据以 [巡检输出契约报告](INSPECTION_CONTRACT_20260926.md) 为准。不得用本页旧哈希声明新增模式仍是未改动的冻结版本。

**本轮选择不修改核心算法，固定当前答辩基线。** 固定的是代码、配置与证据对应关系；真实巡检的标定与验收尚未完成。记录本次文件 SHA-256 的 `defense_freeze_manifest.json` 用于检查基线漂移，不等同于 Git release 或全仓库版本锁定。

## 1. 固定的算法与答辩主线

保留 `Prior-guided Search → Magnetic Detection → Active Cross Scan → Explicit FWHM → Track`，继续使用导航空间坐标、背景修正半峰、双侧交点、有限次数扩幅、沿缆运动门、信号与形状质量门。一次任务预先声明场形及距离换算关系，不在任务中自动挑选新模型。宽度与诊断可保留；垂距和埋深只有在适用前提满足时才有物理意义。

| 内容 | 冻结决定 | 对外定位 |
|---|---|---|
| 当前显式 FWHM、Search/Confirm/Track、两模型形状拒绝门 | 保留现有实现与阈值 | 论文主方法及已验证的拒绝机制 |
| 常系数 `z=κW` | 优先采用，参数须来自目标对象的受控标定 | 同一适用范围内的距离换算 |
| 仿射映射 `z=aW+b` | 保留现有可选接口；常系数确有稳定系统偏差时才考虑 | 标定映射，不作为新的自主场型识别算法 |
| 连续幂律拟合、在线多模型切换、多高度斜率法 | 不进入本次 ROS 答辩主配置 | 适用边界探索与备份页证据 |
| 更大 zig-zag / 新轨迹规划 | 保持已有边界内分档扩幅 | 无完整双侧支撑时拒绝，不无限扩大任务范围 |

**30 秒主讲口径：**

> 本文通过主动横切把磁时间序列转化为有导航坐标的空间剖面，显式提取半高宽，并利用覆盖、信噪比和场形一致性判断观测是否可用。在场形已标定的条件下，宽度量对整体幅值变化更稳定。仿真验证了搜索、确认与跟踪闭环，也暴露了模型失配的拒绝边界。真实部署需要针对目标电缆和工作距离完成独立标定，不能把模型内精度直接解释为海缆实测精度。

## 2. 当前实现事实，避免口径超前

- `cable_tracking_v2_defense.yaml` 使用单直导线及系数 `0.2886751345948129`，服务于对应仿真场景；`cable_tracking_v2.yaml` 使用 `legacy_segment` 与 `0.47203575`，服务于已有 PVS 近似。两者都不是目标真实海缆的现场标定。
- Python v2 pipeline 已有 `depth_calibrations` 和 `affine_depth_calibration` 可选接口。当前 `cable_tracking_v2_node.py` 没有传入这些参数，故不能宣称 ROS 已启用实测标定发布门。
- 当前 Track 的建立依赖有效 FWHM 确认。埋深/场形确认失败时，不会自动转为“只靠磁峰中心继续自主跟踪”。横向中心在复杂或多峰场景下也不是天然可靠的海缆位置。
- 现有 `confidence` 是观测质量评分，不是绝对误差小于某阈值的概率。两模型门只验证了列出的场形混淆，不覆盖全部未知场型。
- 常系数接口尚无通用标定工作范围强制门；仿射接口已有训练宽度范围检查，但仍须现场安装、姿态、高度、位置同步和来源核验。
- 冻结基线不能代替持续跟踪观测更新、数据过期处理和真实传感器链路验收。没有本次重新进行水域或 ROS 动态验收的结论。

## 3. 真实巡检的最短后续路径

后续工作限定为“目标对象标定＋一次部署接线＋验收”。算法形式先固定，再采数据；避免不断换模型来适应同一批验证数据。

1. **限定任务对象和工作范围。** 记录电缆/等效导线结构、相邻磁源、传感器安装与解调通道、横切姿态、拟用距离范围和海床高度基准。对应的是该对象及条件范围，不能把裸直导线标定直接迁移成多芯铠装海缆标定。
2. **做一次受控双侧横切采集。** 建议作为小规模起点：覆盖拟用距离区间的 5 个已知垂距，每个距离 3 次独立横切，共 15 条训练扫描；独立批次另采 15 条测试扫描，含中间距离与反向横切。独立距离真值、同步位姿和高度不可由磁拟合反推。这个数量是收口建议，不是统计充分性证明；测试范围应落在标定覆盖内。
3. **先验固定常系数方案。** 用训练组拟合 `κ`，测试组只做验收。若发现稳定的距离相关偏差，可用训练数据决定仿射方案；已经看过的测试组只能降为开发验证，须再留一批未触碰的数据作最终验收。仿射失败时不继续堆模型，停止把该任务对象的磁 FWHM 作为独立埋深输出。
4. **只做一次 ROS 部署接线。** 在真实巡检专用配置中加载标定来源/身份/适用范围与固定换算关系；缺标定、超范围、动态高度过期或门控失败时不发布深度，显式报告原因。仿真配置仍只用于仿真。复用现有接口完成这次接线，而不重新设计估计器。此项尚未实施，不能仅在 YAML 填 `κ` 就宣布完成。
5. **回放与受控运行验收。** 用未参与开发的记录走“原始测量→位姿/高度→估计→ROS 消息”的实际发布路径；检查拒绝时深度为空、旧值不会被误当新值，以及确认失败后的任务行为。再做受控水池/水域短航段验证，实际作业范围按结果限定。

现有工具默认采用有效率至少 90%、已发布垂距 MAE 不大于 0.2 m、P95 不大于 0.5 m，作为内部筛选门槛。冻结时保留这些门槛；实际任务的误差容限应在采集前约定。另报告全部尝试中“误差超过 0.5 m 仍发布”的比例、漏检/误拒和不确定度；有限样本中零次大误差不代表零风险。垂距通过也不等于埋深通过：后者还须核验同步离底高度及海床基准。

若目前只具备真实数据采集条件，可先进行受控测量与离线回放。不能把“暂不发布埋深”写成当前软件已实现了独立、可直接海试的横向自主跟踪模式。

## 4. PPT 与论文取舍

主讲保留任务流程、显式 FWHM 剖面、轨迹过程和条件精度/拒绝机制。跨场型探索放答问备份页，用来解释标定必要性，不作为在线部署的新算法。主讲不使用“任意场形可迁移”“与模型无关”“真实海缆毫米级埋深”“所有高置信度错误已解决”等表述。

## 5. 冻结与变更规则
